Partner Lab 4 - Write a Program with Modules

Lab 4 is a partner programming assignment - you may complete it with another student from your study group
Purpose

For Lab 4, you and your partner will write a menu-driven program broken up into modules. A menu-driven program gives a user a list of options to choose from, and one of the options should be to quit the program.

As long as your program satisfies the requirements listed below, you and your partner are free to write any program you choose. Examples of menu-driven programs include a banking program with options to print balance, make a deposit, make a withdrawal; a food ordering program with options to purchase different food items; a calculator program with options to add, subtract, multiply, and divide two numbers; a conversion program with options to convert to and from different measurements.

After completing this assignment, you will be able to:

    Collaborate on a program using the online IDE Replit
    Write a menu-driven Python program 
    Organize reusable functions into modules
    Import modules into the main driver program

Task

Using Replit, create a Python program and share an invite link with your partner. Your program must include the following requirements:

    Your program must contain at least three files: the driver program with the main() function and two other module files written by each partner. You must use the import statement to import the module files into the main driver program.
    The main() function will display a menu to the user and continue to loop until the user chooses to quit.
    At a minimum, you must have a function to print the menu, prompt for and return a valid menu option, and a function for each menu choice.
    It must validate the user input. This means the user is not allowed to enter any value. Instead, you must check the value and if it is invalid, ask the user to enter it again and repeat this loop until the user enters a valid value.
    Your program must not crash on any input. In particular, if you are asking for a number, make sure the program doesn't crash if the user enters a non-numeric value, and if you are dividing numbers, make sure your program won't crash on 0 values.
    Organize the code into separate functions: one function for input, one function for output, and one function for each separate calculation or action that the program performs. Each function should be "cohesive" and should only do one thing.
    Use parameters and arguments to pass values into your functions (do not use global variables).
    In the comments box of your submission, answer the following question: When would you need to pass arguments to a function? When is it unnecessary? Explain with an example.

Criteria for Success

    Run your program and test with different user input. Do your prompts explain what the user should enter?
    Take a look at your user interface (UI) and user experience (UX). Did you provide a welcome message letting the user know what to expect? Is the UI nicely spaced with no typos? 
    Please open and compare your work with the Lab 4 Rubric before submitting.
    Remember to follow all Python Style Guide rules for CIS 133Y.
    Include the required comment header with both student names and add comments throughout the code identifying which parts of the program each partner worked on.
    Programs without comments will not be graded - you will be asked to resubmit them with comments before being graded.
    Each student must upload a zip folder with a completed lab4.py file and all other module files to the Lab 4 assignment in D2L and answer the submission question posted on the assignment in D2L.
